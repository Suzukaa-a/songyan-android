## 3. Native 引擎

| 内容 | 路径 |
| --- | --- |
| 从 iOS 同步的引擎源码、补丁、版本钉、levers | `native/src/`、`native/patches/`、`native/grammar/`、`native/lua/`、`native/levers/`、`native/*.env` |
| 来源提交 | `native/UPSTREAM` |
| Android 独有构建与 JNI 胶水 | `native/android/CMakeLists.txt`（取源码、缓存键、JNI 与 `rb_*` 桥、链接）、`native/android/engine/`（librime、依赖、Lua 与插件的静态库子工程，含 `lua-config.h`）、`native/android/exports.map`（链接版本脚本，只导出 JNI 入口与构建标记）、`native/android/jni/rime_jni.cc`、`native/android/jni/jni_guard.h`、`app/proguard-rules.pro`（release R8 对 `RimeNative` 原生方法的 keep） |
| 构建方式 | CMake FetchContent 按 `native/*.env` 的 commit / sha256 拉取依赖到主工作区的 `.local/cmake-deps/`，全部静态链接进 `libsongyan_rime.so`；所有 Gradle 变体一律以 `RelWithDebInfo` 编译引擎（`CMakeLists.txt` 强制），`-fvisibility=hidden`、`--gc-sections`、`--exclude-libs,ALL`，只导出 JNI 入口与构建标记，打包时由 AGP 去符号；`native/patches/` 的 librime 补丁按文件名顺序应用（资源 id 为绝对路径或含 `..` 组件、反斜杠、NUL 时拒绝解析，输入方案配置无法让引擎读写数据目录以外的文件；表文件扩容重映射后重取指针，避免极小词库编译时崩溃；TSV 写入错误上报），octagram instrumentation 也在引擎子工程里完成 |
| 引擎缓存 | `native/android/engine/` 的产物（静态库、打过补丁的 librime 头文件）放在主工作区的 `.local/native-cache/engine-<ABI>-<键>/`（环境变量 `SONGYAN_NATIVE_CACHE` 可改位置），worktree 与 debug / release 共用；键是 `native/*.env`、`native/patches/`、`native/scripts/`、`native/src/*.h`、`native/levers/include/`、`native/android/engine/` 的内容哈希加 CMake / NDK / 编译器版本、ABI、平台与编译参数，任一变化即换新条目；条目编完才写 `.songyan-complete` 并整体改名就位，半成品不会被采用；本机有 `ccache` 时自动作为编译器启动器；旧条目不自动清理 |
| 校验 | `scripts/check-native-engine.sh <apk|build-dir> [--abi ABI]`：所查 ABI（默认三个）都必须带引擎库；APK 内每个 `.so` 的 16 KB 对齐、LOAD 段 2**14 对齐、`JNI_OnLoad` 符号、除 JNI 入口与构建标记外无其他导出、Kotlin `external fun` 与 JNI 符号一一对应、不依赖 `libc++_shared.so`、内嵌 librime 版本与 `native/VERSIONS.env` 一致 |
| 版本来源 | librime 版本取自 `native/VERSIONS.env` 的 `# Release X.Y.Z` 行，由 `core/rime/build.gradle.kts` 生成 `BuildConfig.LIBRIME_VERSION`（Kotlin 侧 `RimeEngine.EXPECTED_RIME_VERSION`） |
| 快照跨界 | `nativeSnapshot` 填充调用方的 `int[]` 并返回 `String[]`（布局见 `rime_jni.cc` 与 `RimeNative.decodeSnapshot`），高亮拼写在同一次调用中读取；`jclass` 在 `JNI_OnLoad` 缓存为全局引用 |
| Release 构建 | `app` 的 release 类型：R8 + `shrinkResources`、AAB 按 ABI 拆分（供 Play）、Gradle 属性 `songyan.abiSplits=true` 时另产出每个 ABI 一个 APK 与一个通用 APK（供 GitHub Release）、`debugSymbolLevel=FULL`；签名读取环境变量 `SONGYAN_KEYSTORE_FILE`、`SONGYAN_KEYSTORE_PASSWORD`、`SONGYAN_KEY_ALIAS`、`SONGYAN_KEY_PASSWORD`，或 git 忽略的 `.local/release-signing.properties`（`storeFile`、`storePassword`、`keyAlias`、`keyPassword`），环境变量优先，都没有时产出未签名包；`versionCode` / `versionName` 在 `gradle.properties` 的 `songyan.versionCode` / `songyan.versionName` |
| CI | [ci.yml](../.github/workflows/ci.yml)：`check`（ktlint、lint、单测、debug 与 release APK、`check-native-engine.sh`；`actions/cache` 按引擎缓存键的输入文件缓存 `.local/native-cache` 与 `.local/cmake-deps`）、`ios-sync`（仅配置了仓库变量 `IOS_REPOSITORY` 时运行 `check-ios-sync.sh`）、`emulator`（x86_64 模拟器 API 29 与 34 上的 `:core:rime` 与 `:ime` 仪器测试，每个模块单独一次 Gradle 调用；GitHub 托管 Linux runner 只能硬件加速 x86_64 模拟器，arm64 由 `check` 构建并检查各 ABI 的引擎库）；[release.yml](../.github/workflows/release.yml)：推送 `vX.Y.Z` 或 `vX.Y.Z-后缀` 标签（须在 `main` 上）后先校验标签与四个签名 secret（`SONGYAN_KEYSTORE_BASE64`、`SONGYAN_KEYSTORE_PASSWORD`、`SONGYAN_KEY_ALIAS`、`SONGYAN_KEY_PASSWORD`），再等待同一提交在 `main` 上的 CI 运行结束（不重复运行；没有可用的 CI 运行或其未通过时失败），通过后以 `songyan.abiSplits=true` 构建已签名的 arm64-v8a、armeabi-v7a、x86_64 与通用 APK（版本名取自标签，版本号为 `git rev-list --count HEAD`，以 Gradle 属性 `songyan.versionName` / `songyan.versionCode` 传入），用 `apksigner`、`check-native-engine.sh` 校验后发布 GitHub Release；带后缀的标签标记为预发布（dev 渠道）；[benchmark.yml](../.github/workflows/benchmark.yml)：每晚与手动触发的 Macrobenchmark，[check-perf-budget.py](../scripts/check-perf-budget.py) 检查显示、按键、上屏耗时的中位数不超过预算 |
| 异常边界 | 每个 JNI 入口用 `jni_guard.h` 的 try/catch 捕获 C++ 异常并返回 fail-closed 值，错误经 `nativeEngineLastError` 上报；编译期依赖版本由 `fetch_git` 的 HEAD 校验兜底 |

从 iOS 同步的文件登记在 [scripts/ios-sync-manifest](../scripts/ios-sync-manifest)，只能由 [scripts/sync-from-ios.sh](../scripts/sync-from-ios.sh) 更新；iOS 工作区在同步路径内有改动时脚本拒绝同步。[scripts/check-ios-sync.sh](../scripts/check-ios-sync.sh) 用 `git show <native/UPSTREAM>:path` 比对记录的提交，不读 iOS 工作区。

| 流 | 链路 |
| --- | --- |

## 6. 存储路径

全部位于应用私有 CE 存储（`filesDir`，v1 不声明 `directBootAware`）：

| 路径 | 内容 |
| --- | --- |
| `rime/sources/<sourceId>/` | 解压后的 Rime 源数据（default.yaml、*.schema.yaml、*.dict.yaml、opencc/、frontend-rime-prelude/）与源清单 `songyan-source.json`（sourceId、类型、显示名、方案列表、revision、条数；[SourceCatalog.kt](../app/src/main/kotlin/app/songyan/ime/storage/SourceCatalog.kt)）；`songyan-builtin`、`user-pinyin`（另存原始词库 `import-sources/`）、`scheme-<包摘要>`；早期版本的 `user-scheme` 仍可读取 |
| `rime/import-staging/incoming-<requestId>/` 与 `staged-<requestId>/` | 设置界面交给部署进程的原始文件（`files/` 或 `package.zip`）与部署进程生成的待部署源树；所有权在 `:deploy`，请求结束后由它删除 |
| `rime/trash/<sourceId>/` | 最近删除的一个源：`tree/` 是源树，`stacked/` 是叠加的词库；只有一份，供设置界面「撤销」，7 天或下一次删除后清除；不含学习数据 |
| `rime/sources/.previous-<sourceId>-<ts>/` | 被替换的源树备份；新 generation 发布成功后删除，部署失败时原样恢复，`active.json` 不指向缺失目录 |
| `rime/deploy/<sourceId>/` | 部署进程私有的工作目录，IME 不读取。部署从空目录开始，先写入部署叠加层，再把同一源、同一引擎最新已发布 generation 的编译词库（源树顶层每个词库的 `.table.bin` / `.reverse.bin` / `.prism.bin` 与全部 `.prism.bin`）复制进 `build/`（[CompiledReuse.kt](../app/src/main/kotlin/app/songyan/ime/deploy/CompiledReuse.kt)；复制而不是链接，因为 librime 原地改写；是否可用由 librime 按校验和判断；复制的文件名记在 `.songyan-seeded`，发布前删掉编译后的 schema 都不提的 prism），librime 在此生成 `build/`。源树与部署写出的配置文件（`.dict.yaml` 除外）的修改时间按内容设定，同样内容的重新导入得到同样的编译 schema，prism 得以复用。发布或失败后删除；发布的记录带 `companionsPending` 时保留并写 `.songyan-pending`，供补全配套方案时接着用；每次取得部署锁时删掉其余工作目录 |
| `rime/stacked-dictionaries/<sourceId>/` | 叠加到该方案包上的词库：`songyan_imported.dict.yaml`、`import-sources/` 原始文件、`user-dictionary.json`；方案包删除时一并删除；`.previous-*` / `.removed-*` 是进行中的替换或移除，中断后下一个部署请求恢复操作前的状态 |
| `rime/versions/<generation>/resources/`、`/build/` 与 `generation.json` | 已发布的不可变 generation（源数据与选中的联想 / 语法模型文件 + 编译产物（含 `songyan-features.json`、`keyboard-adapters.json`）+ 文件清单与发布记录）；`isComplete` 逐文件校验清单 |
| `rime/active.json` | 唯一持久选择记录（v2）：generation、sourceId、schemaId、schemaIds、revision、递增的 sequence、版本戳（应用 / 引擎 / 数据）、createdAt、可选的已应用配置摘要 `configDigest`；只有正在使用的输入方式有配套方案时带 `companionsPending` |
| `rime/keyboard-schema` | 键盘正在使用的输入方式 id，`KeyboardPreferences` 每次改动时写出，供不能读偏好的部署进程决定先生成哪个输入方式的配套方案 |
| `rime/active.lock` / `rime/deploy.lock` | 发布与部署的进程间文件锁 |
| `rime/deploy-status.json` | 部署中 / 失败提示（就绪以 active.json 为准），供 IME 与设置界面显示状态 |
